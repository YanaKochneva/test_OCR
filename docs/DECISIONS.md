# Архитектурные решения

## D-0001: IR является границей между движками и выводом

Движки не передают рендерерам собственные объекты. Единственный контракт между анализом и последующими стадиями — Pydantic IR.

## D-0002: PDFium через pypdfium2

Для чтения и растеризации PDF используется pypdfium2. PyMuPDF намеренно исключён из проекта из-за AGPL.

## D-0003: offline-first

Во время обработки документа сетевые вызовы запрещены. Загрузка моделей является отдельной операцией подготовки окружения.

## D-0004: LGPL-зависимость img2pdf

`img2pdf` разрешён ТЗ только как неизменяемая библиотека-зависимость. Он не модифицируется и помечается отдельно в LICENSES.md.

## D-0005: значения без baseline

Численные пороги качества и latency не придумываются. Они будут заданы после baseline на Фазах 2–4.

## Фаза 3 — Docling

- Базовый режим: `native`. Используется только публичный `DocumentConverter` + `PdfPipelineOptions` + `RapidOcrOptions` + `TableStructureOptions`.
- `layout_only` не активирован: подтверждённого публичного контракта для получения layout-only результата с последующим собственным OCR без приватных API не найдено.
- Для русского OCR выбран `eslav`; английский добавлен как `en`. RapidOCR официально документирует `eslav` для восточнославянских языков и PP-OCRv5.
- Вызовы Docling изолированы в `engines/docling_engine.py`; перед созданием ключевых объектов выполняется `inspect.signature`.
- На текущем checkout Docling отсутствует и сеть отключена, поэтому реальный inference не выполнялся. Контрактный тест остаётся skip с явной причиной.
