# GLM-OCR: подключение VLM

Добавлен движок `glm_ocr`: веб-интерфейс, API, CLI и benchmark могут выбрать его вместо Docling. Он вызывает **полный сервер SDK GLM-OCR**: PP-DocLayoutV3 определяет области, GLM-OCR распознаёт их содержимое. Обычный ответ модели в Markdown без координат не подходит для восстановления расположения объектов.

## Локальный запуск Windows без Docker

Ollama установлен на этом компьютере. Модель и SDK устанавливаются отдельно. Используйте отдельное окружение, чтобы зависимости GLM не изменили рабочее окружение DocPipe. Пример из корня проекта:

```powershell
ollama pull glm-ocr:latest
py -3.12 -m venv .venv-glm
.\.venv-glm\Scripts\python.exe -m pip install "glmocr[selfhosted,server]"
.\.venv-glm\Scripts\python.exe -m glmocr.server --config deploy/glm-ocr-ollama.yaml
```

Для создания окружения нужен установленный Python 3.12. Если Ollama не запущен, в отдельном терминале выполните `ollama serve`. Первая обработка также может скачать модель анализа вёрстки. Требуются свободное место и память. Конфигурация использует анализ вёрстки на CPU и один запрос распознавания одновременно. На GPU 4 ГБ скорость и доступность памяти необходимо оценить при реальном запуске; гарантии размещения всех компонентов в GPU нет.

В другом терминале запустите приложение из его рабочего окружения:

```powershell
& 'D:\AI\venvs\test_OCR\Scripts\python.exe' -m pip install -e '.[glm]'
$env:DOCPIPE_GLM_SERVER_URL = 'http://127.0.0.1:5002/glmocr/parse'
$env:DOCPIPE_GLM_TIMEOUT = '600'
& 'D:\AI\venvs\test_OCR\Scripts\python.exe' -m uvicorn docpipe.api.app:app --host 127.0.0.1 --port 8000
```

Откройте http://127.0.0.1:8000 и выберите **GLM-OCR — VLM**. Ключ для локального сервера не требуется. URL указывает на SDK-сервер порта 5002, а не на Ollama порта 11434. Документы передаются на адрес из `DOCPIPE_GLM_SERVER_URL`; по умолчанию он локальный. Облачный сервис автоматически не используется.

CLI: `python -m docpipe.cli parse INPUT.pdf --engine glm_ocr --out OUTPUT`. Доступные параметры экспорта смотрите через `parse --help`.

## Что сохраняет интеграция

- Текст и типы блоков; заголовки и подписи по native_label.
- Координаты SDK из шкалы 0–1000 переводятся в размеры страницы; сохраняется порядок регионов SDK.
- Таблицы HTML превращаются в ячейки IR с rowspan/colspan. Геометрия отдельных ячеек **вычисляется по сетке**, а не измеряется моделью.
- Изображения повторно вырезаются штатным этапом figures из растра страницы и включаются в экспорт.
- Продолжают работать существующие рендереры и проверки. Отсутствие координат или структуры таблицы выдаёт ошибку, а не маскируется успешной обработкой.

## Статус и оценка

Код подключения добавлен. Реальный запуск GLM и улучшение метрик ещё не подтверждены. VLM может ошибаться или генерировать лишний текст; смена модели сама по себе не исправляет все проблемы шрифтов и размещения. Для сравнения используйте те же пары документов и CER/WER, полноту текста, показатели таблиц и визуальную проверку результатов.

Официальные источники: [GLM-OCR](https://github.com/zai-org/GLM-OCR), [Ollama deployment](https://github.com/zai-org/GLM-OCR/blob/main/examples/ollama-deploy/README.md), [SDK server protocol](https://github.com/zai-org/GLM-OCR/blob/main/examples/self-host/README.md).
