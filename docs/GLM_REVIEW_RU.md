# Повторная проверка через GLM

В интерфейсе выберите **Docling + проверка GLM**. Основной OCR — прежний PP-OCRv5; GLM получает только подозрительные фрагменты. Для этого режима нужен локальный Ollama с моделью `glm-ocr:latest`. Сервер SDK на порту 5002 не требуется: готовые кропы передаются прямо модели без повторной разметки PP-DocLayoutV3.

Перезапуск приложения в PowerShell:

```powershell
Set-Location 'C:\Users\andre\Desktop\test_OCR'
$env:PYTHONPATH = "$PWD\src"
$env:DOCPIPE_GLM_REVIEW_URL = 'http://127.0.0.1:11434/api/generate'
$env:DOCPIPE_GLM_REVIEW_MODEL = 'glm-ocr:latest'
$env:DOCPIPE_API__DEFAULT_ENGINE = 'docling_glm'
& 'D:\AI\venvs\test_OCR\Scripts\python.exe' -m uvicorn docpipe.api.app:app --host 127.0.0.1 --port 8000 --log-level info
```

CLI: `python -m docpipe.cli parse scan.pdf --engine docling_glm --out data/result-review`.

## Правила первого варианта

- Выбираются визуально непустые ячейки и текстовые блоки: пустой результат, смешанные алфавиты, низкая уверенность отдельного OCR-чтения либо расхождение с ним.
- Максимум 2 запроса на страницу; timeout одного запроса — не больше 120 секунд. Проверяются существующие ячейки, отсутствующие в структуре ячейки этот этап не создаёт. Запрос пропускается, если подтверждающее OCR-чтение заранее не проходит правила принятия.
- GLM читает изображение без исходной OCR-подсказки. Новый текст должен совпадать с отдельным OCR-чтением с уверенностью не ниже 0,85.
- Для заполненного фрагмента также проверяются сходство, длина и сохранность чисел. Изменения путей автоматически не принимаются.
- Геометрия, структура таблиц и изображения берутся из основного процесса. Не используется фон исходной страницы.
- Ошибка GLM оставляет основной результат и отключает дальнейшие запросы данного экземпляра движка; перезапуск сервиса позволит повторить попытку. Предупреждение попадает в document.json.
- Решения с исходным текстом, кандидатом, подтверждающим чтением и результатом проверки записываются в журнал `docpipe.stages.glm_review` уровня INFO. Для отдельного JSONL-аудита задайте `DOCPIPE_GLM_REVIEW_LOG` как путь к файлу в существующей папке; document.json содержит краткие счётчики.

Это экспериментальная проверка, а не гарантированная коррекция. Подтверждающий OCR использует ту же модель, что основной этап, на отдельном кропе: ошибки могут совпадать. Пустой, усечённый либо неподтверждённый ответ GLM не используется для замены. Снижение CER/WER требует отдельного полного прогона на документах 3 и 4.
