# Отчёт Фазы 1

## Сделано

- Нормализация входа PDF/изображение с лимитами и SHA-256.
- Анализ текстового слоя без зависимости от языка: кириллица/латиница, управляющие символы, replacement characters и смешение письменностей.
- Растеризация через публичный API `pypdfium2`.
- Контракт `LayoutOcrEngine` и `fake`-движок.
- Геометрические преобразования координат.
- Выделение, объединение, фильтрация и сохранение figure-блоков.
- Закраска областей фигур.
- Детерминированный fallback порядка чтения для колонок.
- Привязка подписей.
- Постобработка текста и режим удаления колонтитулов из потока.
- Markdown и HTML renderer.
- Searchable-PDF fallback на ReportLab с невидимым текстом.
- Базовые проверки результата.
- E2E harness на fake engine.

## Не проверено и почему

- `pikepdf` отсутствует в текущем окружении. Поэтому byte-identical searchable-PDF поверх исходных image streams пока не проверен.
- `img2pdf` отсутствует; преобразование входных изображений в PDF не запускалось.
- Docling и PaddleOCR не установлены; реальные OCR-адаптеры намеренно не объявлены рабочими.
- `ruff` не установлен в текущем runtime, поэтому lint не запускался.
- Зафиксированная версия `pypdfium2==5.13.0` отличается от установленной `5.8.0`; API проверен на реально установленной версии 5.8.0.

## Известные ограничения

- Реальные Docling/PPStructure/PaddleOCR-VL адаптеры пока являются dependency-gated заглушками.
- Searchable-PDF fallback визуально собирает страницу заново и не даёт гарантии идентичности PDF image streams.
- Полный leakage/integrity verifier и debug overlay будут расширены в следующих шагах Фазы 1.
- OCR после masking пока представлен контрактной точкой; реальный движок должен реализовать этот порядок внутри адаптера до подключения в production.

## Допущения

- На Фазе 1 реальное качество OCR не оценивается: эталонный harness переносится в Фазу 2.
- `fake` является единственным обязательным движком для офлайн-тестов.
- Без установленного pikepdf searchable-PDF использует ReportLab fallback.
