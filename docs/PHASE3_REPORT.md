# Отчёт Фазы 3 — Docling

## Сделано

- Реализован адаптер `DoclingEngine`.
- Поддержан режим `native`.
- Режим `layout_only` намеренно не активирован без подтверждённого публичного API.
- Изолирована конвертация страницы через публичный `DocumentConverter`.
- Добавлено преобразование `BOTTOMLEFT -> TOPLEFT`.
- Добавлено преобразование типов Docling в IR.
- Добавлено извлечение таблиц и ячеек в IR.
- Добавлено извлечение picture/chart как `figure`.
- Добавлен runtime-контроль сигнатур через `inspect.signature`.
- Добавлено логирование версии, языков и обнаруженных моделей.
- В `constraints.txt` зафиксирован Docling `2.129.0` как версия, с которой разработан адаптер по публичной документации.

## Известные ограничения

Адаптер в текущем интерфейсе анализирует страницу как отдельное изображение. Это сохраняет контракт `analyze_page(image, page_meta)`, но не является полным native-PDF прогоном одного `DocumentConverter` на весь исходный PDF. Это ограничение текущей архитектуры Фазы 1 и должно быть устранено до production baseline, если требуется строго штатный PDF pipeline Docling.

## Допущения

- Для русского выбраны `eslav` и `en`; официальная документация RapidOCR указывает `eslav` для русского/восточнославянского направления.
- `layout_only` считается неподдержанным до появления проверяемого публичного контракта.
