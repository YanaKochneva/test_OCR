# Готовность к эксплуатации

## Статус

**НЕ ГОТОВ К ЭКСПЛУАТАЦИИ.** Проверка на реальном документе прошла, однако требования к безопасности, жизненному циклу API и нагрузке на больших документах ещё не подтверждены. Пока не следует представлять эту сборку как готовый производственный OCR-сервис.

## Архитектура

В репозитории есть Python-пакет с IR на Pydantic, нормализацией входных данных и растеризацией PDF, адаптерами движков (включая Docling), этапами постобработки рисунков, подписей и порядка чтения, рендерерами, CLI и API заданий на FastAPI. Точка входа конвейера — `docpipe.pipeline.parse`. CLI сохраняет IR и выбранные представления документа; worker API выполняет аналогичный поток.

## Реализовано

- Модели документа, страницы, блока, таблицы и рисунка на Pydantic; генерация схемы.
- Нормализация PDF и изображений, растеризация страниц и анализ текстового слоя.
- Адаптеры OCR-движков: тестовый и опциональные; в среде проверки установлен Docling.
- Обрезка рисунков; код рендереров Markdown, HTML, потокового и поискового PDF.
- Команды CLI для разбора, проверки, диагностики и просмотра моделей; endpoints API заданий и код worker.
- Команда `docpipe eval` для сравнения IR с DOCX-эталоном по точности/полноте токенов, CER и WER с сохранением порядка абзацев и таблиц.
- Проверка результата: разбор IR, статусы страниц, геометрия, таблицы, файлы и поток рисунков, подписи, утечки текста, артефакты и текст поискового PDF.
- Веб-интерфейс загрузки и получения архива; production defaults выбирают Docling, пустой результат реального OCR отклоняется.

## Проверено

- `python --version` → Python 3.13.16.
- `python -m pip check` → конфликтов зависимостей нет.
- `python -m pytest -q` → 40 тестов пройдены, 1 пропущен.
- `python -m pytest -q -m engine_docling` → 1 тест пройден.
- `python -m docpipe.cli --help` → справка CLI отображается.
- `python -m docpipe.cli doctor` → `ok: true`; отсутствие необязательного PPStructure и GPU отмечено как WARN.
- `python -m docpipe.cli models list` → движок `fake`, включён автономный режим.
- Реальный входной PDF обработан Docling 2.134.0: 15/15 страниц OK, 17 509 распознанных символов, 12 таблиц, 17 рисунков, утечек текста из рисунков нет. `docpipe verify data/quality_reference_run` → PASS; поисковый PDF содержит извлекаемый кириллический текст.
- Сквозная API-проверка реального PDF завершилась статусом `completed`; архив содержит JSON, Markdown, HTML, оба PDF, DOCX, рисунки, `verification.json` и `metrics.json`; verifier в API-архиве → PASS.
- Сравнение с DOCX-эталоном: precision 93,4%, recall 83,0%, F1 87,9%, CER 14,4%, WER 19,2%. Сравнение сохраняет порядок абзацев и таблиц; DOCX не хранит надёжную постраничную OCR-разметку.

## Производительность

Разбор реального 15-страничного документа с Docling в API занял 116,59 секунды (`parse_total`, без рендеринга). Синтетический стресс-прогон на 300 страницах с тестовым OCR-движком завершился за 10,55 секунды; пиковый RSS процесса — 219 664 384 байта. Это проверяет растеризацию и обработку страниц, но не нагрузку самой OCR-модели. Стресс-тест 300 страниц с реальным движком не выполнялся.

## Безопасность

Лимит размера файла применяется к асинхронной и синхронной загрузке; синхронный endpoint не блокирует event loop, а ошибочный PDF получает ответ 422. API-ключ проверяется, его длина должна быть не менее 32 символов; `doctor` предупреждает, когда ключ не настроен и API принимает запросы без аутентификации. Проверены некорректный PDF, неподдерживаемые форматы результата и запрос без ключа. Ограничение частоты запросов, защита от вредоносных файлов, TLS/прокси и сквозные тесты эксплуатационной конфигурации всё ещё не подтверждены.

## Лицензии

В репозитории есть `LICENSES.md` и скрипт проверки лицензий. Полная проверка образа развёртывания и SBOM в этом цикле не проводилась, поэтому разрешение на распространение не подтверждено.

## Известные ограничения

- Для русского PDF исправлена критичная ошибка конфигурации: PNG-страницы передавались в Docling без OCR-настроек, привязанных к формату IMAGE. После исправления полнота точного совпадения токенов с DOCX выросла с 5,7% до 83,0%. Остаточные ошибки OCR есть; пороги для производственного применения заказчиком не заданы.
- Визуальное качество рисунков и поведение выделения текста в предоставленном PDF вручную не проверялись; извлечение текста и число страниц проверку прошли.
- PPStructure не установлен, GPU не настроен.
- Реальная OCR-модель не проверялась в 300-страничном стресс-прогоне; security- и интеграционные проверки развёртывания не завершены.
- Метаданные OCR-моделей и детерминированность результата нужно проверить на реальных прогонах.

## Оставшиеся блокеры

1. Утвердить пороги OCR и проверить их на нескольких размеченных документах; текущий один DOCX-эталон даёт precision 93,4%, recall 83,0%, CER 14,4%, WER 19,2%.
2. Настроить API-ключ в целевом окружении; проверить rate limiting, вредоносные файлы, TLS/прокси и нагрузку больших документов с реальной OCR-моделью.
3. Проверить лицензии включённых моделей и зависимостей, а также автономный запуск фактического образа развёртывания.

## Развёртывание

Dockerfile устанавливает Docling, загружает нужные модели в образ и запускает приложение под непривилегированным пользователем. Compose выбирает Docling, включает автономный режим и требует API-ключ. Сборка контейнера и smoke-тест развёртывания ещё не выполнялись из-за DNS-сбоя при загрузке базового образа; локальный сквозной API-прогон прошёл.

## API

Приложение FastAPI и worker заданий реализованы. До публикации сервиса необходимо сквозным образом проверить аутентификацию, семантику readiness, ограничение параллелизма, повторное использование worker и корректное завершение.

## Конфигурация

Конфигурация описана через Pydantic Settings и YAML; в репозитории есть `config.example.yaml`. Команда `doctor` проверяет Python, пакеты, шрифт, рабочую директорию, OCR-бэкенд и автономный режим.

## Модели

В реальном прогоне использовались Docling 2.134.0 и локальные файлы моделей RapidOCR. Модели уже находились на диске; этот прогон не проверял чистую автономную установку и процесс подготовки моделей. PPStructure отсутствовал.

## Результаты тестов

Набор модульных тестов и тест с маркером Docling проходят в настроенной среде Windows; приёмочный прогон на реальном документе также прошёл. Этого недостаточно для подтверждения готовности к эксплуатации: остаются непроверенными безопасность, жизненный цикл API, нагрузка и развёртывание.
