# Компоненты DocPipe: назначение и обоснование

Состояние после очистки 13 октября 2026 года. Основной маршрут: Docling + PP-OCRv5.

## Папки и корневые файлы

| Компонент | Что делает и зачем нужен |
|---|---|
| `src/docpipe/` | Рабочий код конвейера, интерфейса, рендеринга и оценки. |
| `docs/` | Инструкции, текущая схема, спецификация данных и обоснования архитектуры. |
| `deploy/` | Настройки контейнера и опционального сервера GLM. |
| `scripts/` | Проверка лицензий и генерация схемы данных. |
| `eval/` | Отдельный инструмент сравнения с эталонным DOCX. |
| `data/jobs/`, `reports/` | Пустые папки будущих заданий и результатов оценки; создаются/наполняются при запуске. |
| `.github/workflows/ci.yml` | Ruff, mypy и проверка лицензий. Запуск удалённых тестов исключён. |
| `.vscode/extensions.json` | Рекомендации расширений редактора для работы со схемами. |
| `.git/` | История и рабочее состояние репозитория. Не очищалась и не переписывалась. |
| `src/docpipe.egg-info/` | Метаданные editable-установки; сохранены, чтобы не ломать установленный пакет. Генерируются установщиком. |
| `README.md` | Начальная инструкция и запуск приложения. |
| `pyproject.toml` | Описание пакета, зависимости, команды и настройки разработки. |
| `constraints.txt` | Ограничения версий для воспроизводимой установки. |
| `requirements-docker.txt` | Отдельный перечень зависимостей CPU-контейнера. |
| `config.example.yaml` | Пример настройки лимитов, обработки и API. |
| `Dockerfile` | CPU-контейнер с подготовкой моделей. |
| `Dockerfile.cuda` | Опциональный шаблон GPU-контейнера; требует отдельной проверки и подготовки OCR-зависимостей. |
| `.gitignore`, `.dockerignore` | Исключают результаты, кэши, окружения и секреты из Git/контекста сборки. |
| `LICENSES.md` | Лицензии используемых компонентов. |

## Ядро — `src/docpipe/`

| Файл | Что делает и зачем нужен |
|---|---|
| `pipeline.py` | Обрабатывает страницы и собирает общий документ; единая точка конвейера. |
| `ir.py` | Типизированные страницы, блоки, ячейки и рисунки; единые данные для всех экспортов. |
| `config.py` | Централизованные настройки YAML/окружения и лимиты. |
| `errors.py` | Общие типы ошибок для согласованных сообщений о сбоях. |
| `cli.py`, `__main__.py` | Командный запуск обработки, диагностики, проверки и оценки. |
| `doctor.py` | Диагностика зависимостей и окружения. |
| `quality.py` | Диагностика распознанного документа без эталона. |
| `evaluation.py` | Сравнение с эталоном и метрики CER/WER. |
| `benchmark.py` | Оценка пар «эталон / скан» и формирование отчётов; сохранена как функция приложения. |
| `error_analysis.py` | Анализ замен, вставок и пропусков для объяснения плохих метрик. |
| `__init__.py` | Определяет Python-пакет; аналогичные файлы подпапок обеспечивают импорт. |

## Интерфейс, ввод и растеризация

| Файл | Что делает и зачем нужен |
|---|---|
| `api/app.py` | HTTP-маршруты загрузки, состояния, результатов и готовности; обслуживает веб-страницу. |
| `api/jobs.py` | Очередь, выполнение, статусы заданий и очистка результатов по сроку хранения. |
| `api/static/index.html` | Страница загрузки документа и скачивания результата. |
| `io/normalize.py` | Проверяет вход и приводит изображения к PDF. |
| `io/textlayer.py` | Анализирует наличие и признаки качества текстового слоя. |
| `render/raster.py` | Создаёт изображение страницы с заданным DPI и сохраняет размеры. |

## Движки — `engines/`

| Файл | Что делает и зачем сохранён |
|---|---|
| `base.py` | Общий контракт: одинаковый формат входа и результата разных движков. |
| `__init__.py` | Фабрика выбора движка; отложенные импорты опциональных компонентов. |
| `docling_engine.py` | Основной адаптер Docling / PP-OCRv5, объединяющий разметку, OCR и восстановление. |
| `glm_ocr_engine.py` | Явно выбираемый адаптер GLM-OCR; сохраняет существующую интеграцию. |
| `glm_crop_reader.py` | Опциональное повторное чтение фрагментов через Ollama. |
| `ppstructure_engine.py` | Опциональный PPStructure, доступный через существующий выбор движков. |
| `paddleocr_vl_engine.py` | Опциональный PaddleOCR-VL, не основной маршрут. |
| `fake_engine.py` | Явно выбираемый диагностический движок, не реальное OCR. Сохранён из-за действующего контракта CLI/API; тестовые фикстуры удалены. |

Неиспользуемые `tesseract_reader.py` и `code_columns.py` удалены: ссылок на них
в рабочем коде не было. Доступные через фабрику альтернативы сохранены, чтобы
очистка не меняла API. Наличие адаптера не означает включение в основной маршрут.

## Восстановление — `stages/`

| Файл | Что делает и зачем нужен |
|---|---|
| `geometry.py` | Преобразование и сравнение координат; разделяет пиксели и единицы страницы. |
| `order.py` | Геометрический порядок чтения и разделение колонок. |
| `ocr_recovery.py` | Возвращает OCR-строки, не попавшие в структурные блоки. |
| `text_refinement.py` | Сопоставляет повторное OCR с блоками и проверяет допустимость изменений. |
| `word_refinement.py` | Повторное чтение отдельных слов; также содержит явно включаемые экспериментальные варианты. |
| `mixed_scripts.py` | Сопоставление смешанной кириллицы и латиницы. |
| `path_recognition.py` | Повторное чтение путей и разделителей. |
| `recognition_consensus.py` | Согласование нескольких визуальных вариантов OCR. |
| `short_value_consensus.py` | Дополнительная проверка коротких значений таблиц. |
| `table_reconciliation.py` | Привязка OCR-строк к ячейкам по координатам. |
| `cell_recovery.py` | Повторное чтение ячеек и защитные условия замены текста. |
| `table_geometry.py` | Уточнение сетки и областей повторного чтения ячеек. |
| `table_coverage.py` | Анализ покрытия таблицы текстом для восстановления пропусков. |
| `figures.py` | Фильтрация, объединение и вырезка рисунков. |
| `captions.py` | Связывание подписей с рисунками. |
| `postprocess.py` | Завершающие правила обработки блоков и колонтитулов. |
| `repeated_margins.py` | Классификация повторяющихся колонтитулов по нескольким страницам. |
| `orientation.py` | Опциональная проверка поворота страницы. |
| `masking.py` | Опциональное исключение рисунков из повторного OCR. |
| `cell_borders.py` | Опциональная очистка границ ячейки перед чтением. |
| `alternate_recognition.py` | Опциональное согласование дополнительного распознавания строк. |
| `line_confirmation.py` | Сравнение строк при опциональном подтверждении через GLM. |
| `glm_review.py` | Условия принятия результатов повторной проверки GLM. |

Опциональные модули оставлены, поскольку на них ссылается движок.
Экспериментальные переключатели по умолчанию выключены; сохранение файла
не означает подтверждённое улучшение качества или обязательное выполнение этапа.

## Что удалено

Тестовые наборы `tests/`, временные скрипты `data/`, старые результаты обработки,
отчёты `reports/`, логи, кэши Python/pytest, `.qa-deps`, временный TOML,
нагрузочные скрипты, фазовые отчёты и старые схемы с генераторами.
Также удалены экспериментальные локальные EasyOCR и portable Tesseract,
которые не используются основным маршрутом.

Основные модели и Python-окружение вне проекта не удалялись. Пользовательские
исходники вне проекта не затрагивались. История Git не переписывалась:
удалённые отслеживаемые файлы остаются в истории. Новый OCR-прогон при очистке
не выполнялся; промышленная готовность очисткой не подтверждается.

## Проверка после очистки

Успешно разобраны 69 Python-файлов и `pyproject.toml`. Отсутствующих внутренних
импортов не обнаружено. Импорт API прошёл, зарегистрированы 14 маршрутов.
Это проверка целостности кода, а не полный OCR-прогон или подтверждение качества.
