# Асинхронный OCR для мультиагентной платформы

Авторизация выполняется платформой; Docker Compose отключает проверку API-ключа OCR.
Один процесс Uvicorn обслуживает очередь; несколько агентов могут подавать задания.

## 1. Создать задание

`POST /v1/jobs`, multipart/form-data:

- `file`: один PDF или изображение (обязательно).
- `request_id`: идентификатор запроса платформы, 1–200 символов (необязательно).
- `options`: JSON-строка с `engine` и `outputs` (необязательно).

```sh
curl -F "file=@scan.pdf" -F "request_id=platform-task-42" http://localhost:8001/v1/jobs
```

Ответ HTTP 202: `job_id`, `request_id`, `status`, `progress` (0–100),
`pages_total`, `review_required`, `error`, `created_at`, `started_at`,
`finished_at`, `expires_at`, `links`.
Время — Unix timestamp в секундах; неизвестные значения времени — null.
Заголовок `Location` указывает статус задания, `Retry-After: 2` — интервал опроса.
`request_id` сохраняется с заданием и служит для сопоставления, а не дедупликации:
повторный POST создаёт новое задание. При неопределённом результате POST
не повторяйте загрузку автоматически.

## 2. Проверять состояние

`GET /v1/jobs/{job_id}` возвращает те же поля.
Опрос каждые 2 секунды до терминального состояния:

| status | Действие платформы |
|---|---|
| queued | Подождать: документ в очереди |
| running | Показать progress и продолжить опрос |
| completed | Получить JSON и/или ZIP |
| failed | Прочитать error, сообщить об ошибке |
| cancelled | Завершить ожидание |

`progress` отражает ход обработки, а не точную оценку оставшегося времени.
`completed` не гарантирует безошибочное OCR: проверяйте `review_required`,
предупреждения и статусы страниц в документе.

## 3. Получить результат

- `GET /v1/jobs/{job_id}/document`: JSON для агента, поля `job_id`, `request_id`,
  `review_required`, `text`, `document`. `text` объединяет текст блоков и ячеек
  таблиц в порядке чтения. `document` содержит полную структуру страниц,
  координаты, таблицы с ячейками и ссылками на изображения.
- `GET /v1/jobs/{job_id}/result`: ZIP с экспортами и отчётами.
- `GET /v1/jobs/{job_id}/files/{path}`: отдельный файл из комплекта, например
  `document-positional.pdf` или изображение по пути из структуры документа.

Относительные ссылки `links` разрешаются относительно адреса OCR-сервиса.
Результаты по умолчанию хранятся один час после завершения; срок указан в `expires_at`.
Затем запрос вернёт 404. Сохраняйте нужные результаты на стороне платформы.

## Ошибки и перезапуск

Ошибки содержат `error.code`, `error.message` и совместимое поле `detail`.
Коды: `invalid_request`, `not_found`, `result_not_ready`, `limit_exceeded`,
`unsupported_format`, `queue_full`, `service_unavailable`, `processing_failed`,
`timeout`, `server_error`.
HTTP 409 означает, что результата для текущего состояния нет: проверьте статус.
HTTP 429 означает заполненную очередь; новую подачу можно отложить.
Ошибка самого фонового OCR находится в `error` ответа статуса при `status=failed`.

Очередь находится в памяти. После перезапуска незавершённые задания становятся
`failed`, завершённые восстанавливаются из тома Docker до истечения TTL.
`request_id` также сохраняется. Гарантированного выполнения при перезапуске нет.

с идентификатором задания, JSON для агента и ZIP; таймаут клиента не отменяет OCR.
Для отмены ожидающего задания или удаления результата: `DELETE /v1/jobs/{job_id}`.
Выполняющееся задание удалить этим методом нельзя.
