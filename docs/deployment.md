# Развёртывание и инженерные проверки

## Установка

Минимальная версия Python — 3.11; Docker использует Python 3.11 и CPU.
Зависимости приложения и extras определены в `pyproject.toml`.
`requirements.txt` подключает локальный пакет с extras `docling,nemotron-review`.
`constraints.txt` задаёт ограничения версий при установке и в CI.
Это не полный lock-файл всех транзитивных зависимостей.

```sh
python -m pip install -r requirements.txt
python -m pip check
```

RapidOCR 3.9.1 указан явно из-за совместимости Docling с его API.
ONNX Runtime входит в OCR-extra. Принудительная установка пакетов с
`--no-deps` в Docker больше не используется. Docker загружает модели при
сборке; для рабочего процесса они находятся внутри образа. Для локальной
установки подготовьте модели по инструкции README.

## Конфигурация

По умолчанию OCR локальный, LLM/VLM выключены. Внешняя проверка включается
явно. Неизвестные поля YAML отклоняются, переменные окружения имеют приоритет
над YAML. Если включена проверка API-ключа, пустой ключ блокирует запуск.

Compose публикует порт только на loopback. Для встроенной аутентификации:
`DOCPIPE_REQUIRE_API_KEY=true` и `DOCPIPE_API_KEY` длиной не менее 32 символов.
При прямом запуске используются `DOCPIPE_API__REQUIRE_API_KEY` и
`DOCPIPE_API__API_KEY`. Эти группы имён различаются, потому что Compose
переводит значения своего env-файла в переменные процесса приложения.
Значения секретов не помещаются в репозиторий.

## Процессы и данные

Запускайте один процесс Uvicorn (`--workers 1`): очередь и состояние workers
находятся в памяти, а метаданные заданий — в каталоге `data/jobs`.
Несколько процессов не разделяют одну очередь. Увеличение числа процессов
требует изменения архитектуры хранения и диспетчеризации.

При рестарте прерванные задания переходят в failed; их нужно отправить заново.
Пути из сохранённых метаданных проверяются относительно work_dir перед
обращением к входным файлам и результатам. Встроенная очистка учитывает TTL.
Копируйте каталог заданий и сохраняйте права доступа при переносе сервиса.
Каталоги `data`, `reports`, `models` исключены из Git и Docker-контекста.

Реестр OCR рассчитан на одного писателя на каталог результата. JSON заменяется
атомарно, решения дописываются в журнал. Между записью события и обновлением
JSON возможен сбой; это не транзакционная база данных. Подробности:
[ocr-issues.md](ocr-issues.md).

## Состав поставки

В репозитории остаются runtime-код сервиса, конфигурация, эксплуатационная
документация и скрипты подготовки моделей. CI собирает пакет, проверяет
Compose и собирает Docker-образ. Тесты, бенчмарки, примеры клиентов и
модуль расчёта метрик по эталонам в поставку не входят.

Runtime-проверки экспорта и реестр сложных случаев OCR остаются частью сервиса.
Адаптеры OCR сохраняют обработку узких кропов и рекомендованный padding
русской модели — они необходимы для распознавания.

Docker Engine на машине подготовки не запущен: новая сборка и запуск образа
пока не подтверждены. Перед переносом проверьте образ в целевом окружении.
