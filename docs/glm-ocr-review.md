# Перепроверка GLM-OCR

Локальная опциональная перепроверка через Ollama. По умолчанию отключена.

## Как работает перепроверка

1. Исходная страница растеризуется с учётом поворота и координат OCR.
2. Текстовый блок или ячейка вырезается с небольшим полем.
3. GLM получает только изображение и фиксированный prompt `Text Recognition:`.
   JSON Schema, исходный OCR-текст и DOCX-эталон модели не передаются.
4. Транскрипция сопоставляется с исходным OCR. Короткие, несходные или
   незавершённые ответы отклоняются. Текстовые блоки не удаляются.
5. Принимаются только близкие замены неизвестного слова на слово независимого
   русского словаря. Правильные словарные слова, аббревиатуры, числа, пути,
   имена файлов и переносы с дефисом защищены. Неизвестные термины не угадываются.
6. Исправления обновляют текст блока, строки и HTML таблиц. Сохраняются
   исходный текст, распознанная версия и хеш изображения; изменения отмечаются
   для проверки. После экспорта работают детерминированные проверки содержимого.

Транскрипции кешируются по модели и изображению. Кеш не содержит эталона
и позволяет повторять оценку и сборку без повторного инференса.
DOCX используется только после завершения распознавания для расчёта метрик.

## Подготовка

В установленном `glm-ocr:latest` с ID `6effedd0dc8a` отсутствовал EOT:
правильно прочитанный текст повторялся до лимита токенов. Подготовлена
отдельная модель `docpipe-glm-ocr:latest` с добавленным
`tokenizer.ggml.eot_token_id = 59253` (`<|user|>`).
Исходный GGUF сохранён, байты тензоров совпадают по SHA-256:
`f3bfd4f66fd423546cd1b28be0caa4c82f438c9a6947947cc2137cfe7d81aaf2`.
Это исправление метаданных, без обучения и изменения весов.

Для повторения на машине с той же исходной моделью:

```powershell
python -m pip install -e ".[glm-review]"
New-Item -ItemType Directory -Force models/glm-ocr
# Замените SOURCE_GGUF на путь FROM из команды ollama show glm-ocr --modelfile.
python scripts/fix_glm_gguf.py SOURCE_GGUF models/glm-ocr/model-eot.gguf
ollama create docpipe-glm-ocr -f configs/Modelfile.glm-ocr
```

Скрипт проверяет архитектуру, словарь токенов и неизменность весов;
существующий файл не перезаписывает. Если модель уже имеет EOT, ремонт
не нужен: укажите её имя в `review.api_model`.

## Запуск

```powershell
$env:PYTHONPATH = 'src'
python -m docpipe.cli parse input.pdf --config configs/glm-ocr-review.yaml --out reports/glm-run
```

Для Docker Desktop:

```powershell
docker compose -f deploy/docker-compose.yml -f deploy/docker-compose.glm-ocr.yml up --build
```

Исправленная модель должна быть создана в Ollama на хосте. Для доступа
контейнера используется `host.docker.internal:11434` и `offline=false`.
Для обычного локального запуска при `offline=true` разрешён только loopback.

## Артефакты и проверки

Результаты — указанный каталог `--out`: `review-before.json`, `review-glm-reread.json`, `review-after.json`,
`document.json`, PDF и HTML. Отчёт содержит исходный текст документа и
предназначен для локального анализа.

Первоначальный эксперимент с JSON-корректурой и визуальным сравнением не
используется в текущем режиме. GLM теперь повторно распознаёт изображение;
оценка вёрстки произвольным JSON-запросом отключена.
