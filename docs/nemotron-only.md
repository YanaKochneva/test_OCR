# Прямой тест Nemotron 3.5 Parse

Из корня проекта с установленными зависимостями `.[nemotron-review]`:

```powershell
python -m docpipe nemotron-only "C:\documents\doc_txt_006.pdf" --out output/nemotron-only/doc_txt_006.pdf
```

Укажите реальный путь входного документа. Локальная модель по умолчанию:
`models/nemotron-3.5-parse`. Другой путь и устройство:

```powershell
python -m docpipe nemotron-only input.pdf --model "D:\models\nemotron-3.5-parse" --device cuda:0 --out output/nemotron-only/result.pdf
```

Поддерживаются PDF и изображения Pillow (включая многостраничные TIFF).
PDF растеризуется постранично при `--dpi 150`; текстовый слой не читается.
На каждую полную страницу выполняется ровно один `model.generate` с официальным
промптом Nemotron. Модель загружается один раз, только из локальных файлов;
при `--device auto` используется CUDA при наличии, иначе CPU.

Docling, RapidOCR, выделение кропов, исправления, консенсус, другие LLM и
проверки основного конвейера не запускаются. Настройки основного конвейера
не используются. Применяется только штатный процессор входа самой модели.

Nemotron возвращает строку, а не PDF. Команда печатает декодированную строку
в PDF с переносами длинных строк, без разбора или очистки. Служебные токены,
координаты и Markdown/HTML остаются видимыми: это PDF с сырым ответом модели,
а не восстановленная верстка исходного документа. Каждая исходная страница
начинается с новой страницы PDF; длинный ответ может занимать несколько страниц.

Лимит генерации задаётся `--max-new-tokens 8744`. При достижении лимита без EOS
или пустом ответе команда завершается с ошибкой и не создаёт новый PDF.
На CPU полный документ может обрабатываться долго.

Точный ответ также сохраняется в `<имя-результата>.raw.json` после каждой
страницы. Поле `complete` становится `true` только после полного успешного
прогона. Сборщик использует этот JSON, если он есть: служебные токены, Unicode
и переносы сохраняются без обратного извлечения текста из PDF. Для старых
результатов без JSON остаётся восстановление ответа из PDF.

## Сборка по координатам с оригинальными изображениями

```powershell
python scripts/rebuild_nemotron_pdf.py output/nemotron-only/doc_txt_006.pdf "C:\documents\doc_txt_006.pdf" output/pdf/doc_txt_006-with-images.pdf --image-regions configs/nemotron-doc-txt-006-images.json
```

Скрипт использует сохранённый ответ, модель повторно не запускает. Графические
блоки `Picture`, `Figure`, `Image`, `Logo`, `Chart`, `Graphic` вырезаются из
оригинальной страницы при 300 dpi (`--image-dpi`). Небольшие встроенные растровые
изображения цифрового PDF также сохраняются. Крупные растровые слои сканов
исключаются: они содержат и текст страницы.

PNG сохраняются в `<имя-результата>-images/`. В этой же папке `manifest.json`
содержит номер страницы, имя файла, координаты относительно верхнего левого
угла (нормализованные и в PDF points), размеры и DPI. При сборке каждый PNG
вставляется по этим же координатам, без изменения пропорций. Текстовые блоки,
покрытые картинкой, повторно не печатаются.

Блоки `Table` собираются в таблицы с ячейками и объединениями из HTML/LaTeX
ответа модели. Для LaTeX используется официальный постпроцессор из локального
`models/nemotron-3.5-parse`, без дополнительного распознавания. Ширина столбцов
и размер шрифта подбираются внутри предсказанного блока; исходное оформление
таблиц (например, заливка) не воспроизводится точно.

Если Nemotron не выделил картинку или прочитал логотип как текст, задайте
область явно через `--image-regions`: JSON-массив объектов
`{"page": 2, "bbox": [0.075, 0.014, 0.305, 0.060]}`. Страницы нумеруются с 1,
координаты `[left, top, right, bottom]` лежат в диапазоне 0–1. Конфигурация
`nemotron-doc-txt-006-images.json` содержит вручную выделенные области логотипов
на страницах 2–4 этого конкретного теста. Это не автоматическое обнаружение
всех изображений в произвольных сканах. Векторные иллюстрации без выделенного
моделью блока также требуют явной области; сохранение выполняется в PNG.
