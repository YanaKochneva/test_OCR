# Реестр сложных случаев OCR

Каждый запуск CLI/API создаёт `review/issues.json`, `review/index.html`,
`review/crops/*.png` и `review/decisions.jsonl` в каталоге результата.
VLM для этого не требуется. Повторный parse в ту же папку переносит прежний
реестр, журнал, кропы и отчёты GLM/fallback в `review-archive-<uuid>/`.
Архивы содержат текст документов; срок их хранения задаёт владелец каталога.

В реестре сохраняются SHA-256 исходного файла, ID запуска, время UTC,
версия OCR-движка и параметры обработки без секций API и доступа к моделям.
Рамки `bbox_pt` используют координаты IR с учётом поворота страницы.
`original_text` сохраняется до GLM, альтернативы GLM хранятся отдельно.
Ошибки получения кропа записываются как `crop_error` и не останавливают OCR.

Причины: `low_confidence`, `confidence_unavailable`, `mixed_script`,
`invalid_characters`, `image_fallback`, `page_warning`, `page_degraded`,
`page_failed`, `ocr_disagreement`, `glm_proposal`.
Отсутствующий confidence имеет severity `info` и само по себе не требует
ручной проверки. Остальные незакрытые проблемы входят в `review_required`
в CLI metrics и API status. Наличие проблемы не означает доказанную ошибку.
Проверки пропусков текста и произвольной структуры таблиц этим модулем
не выполняются; фиксируются уже обнаруженные fallback-области и предупреждения.

Confidence строки и ячейки хранится в IR. Для группы совпадающих OCR-строк
используется средняя оценка, взвешенная по числу символов. Минимум оценок
отдельных строк используется для отметки проблемы в реестре, а не для
замены всего абзаца картинкой. Оценка не переносится на другой текст.
GLM confidence не присваивается. Его предложения остаются на проверке.

Закрыть проблему (подтвердить завершение проверки):

```powershell
python -m docpipe.cli review-decision reports/run "p1:text" confirmed --actor operator --source-sha256 HASH --note "Checked against scan"
```

`dismissed` означает ложное срабатывание; `unresolved` открывает проблему снова.
Команда обновляет JSON и HTML и дописывает событие в журнал. Это решение о
проверке, оно не меняет текст документа и экспорт. `accepted_text` зарезервирован
для отдельного механизма редактирования; сейчас null. Автоматические исправления
GLM продолжают фиксироваться в существующем `review-glm-reread.json`.
Для изменения одного каталога результата требуется один писатель одновременно.
JSON записывается через временный файл и атомарную замену. Журнал пишется первым;
при сбое между журналом и JSON последний event может ещё не отражаться в JSON.
